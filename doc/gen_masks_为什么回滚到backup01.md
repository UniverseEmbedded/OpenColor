## 结论

当前阶段（2026-02），`gen_masks` 以 `main_backup01.py` 对应的流程作为默认最佳方案。

我们尝试过把“联合优化”扩展到全层，并增加更激进的后置清理（小连通域剔除、去单像素等），但在实际图片上出现了两类不可接受的问题：

- 细线/线稿破碎甚至消失（结构信息被破坏）
- 出现类似 JPEG 后遗症的“块状小方格”（视觉伪结构被放大）

这两点会直接影响下游打印掩码质量，因此决定回滚。

---

## 为什么新尝试会变差

### 1) 全层联合优化更容易“破坏结构”

全层联合优化本质是在像素级上做大量局部替换，它会在边界附近做更细粒度的决策。

当优化目标（色差项、平滑项、混色项、岛屿项）出现权重不匹配时，很容易出现：

- 线条边缘被局部替换，导致连通性断裂
- 细线被当作“噪声小块”逐步消解

即使后续做清理，也常常是“修不回来的结构损失”。

### 2) 更激进的后置清理会“误杀”细线

面积阈值/连通域剔除在视觉上很有效，但对 1px~2px 的线条端点、交叉点非常敏感。

一旦联合优化让细线出现极短的断裂，后置清理会把这些断裂段当作小碎岛替换掉，最终造成“线条缺失”。

### 3) “块状小方格”的根因是伪结构被算法强化

输入图像即使是 PNG，也可能来自 JPEG（或经历过压缩/重采样），在局部会存在块状的色彩微差。

当像素级优化把这些微差当成真实结构去追随，就会产生块状分界；再叠加某些平滑/映射步骤，块状伪结构会变得更显眼。

---

## 当前默认流程（回滚后）保留了什么

回滚到 backup01 版本后，默认策略是：

- `postprocess_mode` 默认使用 `joint`
- `joint_l0_enabled` 默认关闭（需要时手动开启）
- 即使开启联合优化，也只对“首层（L0）”做联合优化（`layer_end=1`）

这样做的目的，是在“色准/干净”与“结构稳定（不断线、不块化）”之间取一个更稳妥的折中。

## 操作建议

### 生成掩码（默认推荐）

```bash
pixi run p2-gen-masks --image-path "data/image/龙娘.png"
```

### 需要尝试首层联合优化时

```bash
pixi run p2-gen-masks --image-path "data/image/龙娘.png" --joint-l0-enabled
```

如果要继续做“更强的结构保真 + 去噪”，建议以单独分支/单独入口脚本进行实验，不要覆盖默认流程。
