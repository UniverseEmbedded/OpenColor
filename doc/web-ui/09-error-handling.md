# 错误处理策略

本文档定义 OpenColor WebUI 的错误处理策略，包括错误分类、处理层级、用户提示和恢复机制。

## 错误分类

### 按层级分类

| 层级 | 错误类型 | 示例 | 处理责任 |
|------|----------|------|----------|
| Web 前端 | UI 错误 | 表单验证失败、网络请求超时 | 前端组件 |
| Rust 后端 | 系统错误 | 文件读写失败、进程通信失败 | Rust API 层 |
| Python 引擎 | 业务错误 | 训练失败、求解失败、数据格式错误 | Python 引擎 |
| C++ 求解器 | 计算错误 | 内存不足、数值溢出 | C++ 求解器 |

### 按严重程度分类

| 级别 | 说明 | 示例 |
|------|------|------|
| warn | 警告，可自动恢复 | 使用 CPU 代替 GPU |
| error | 错误，需用户干预 | 文件被占用 |
| fatal | 致命错误，应用崩溃 | 内存耗尽 |

## 错误代码规范

### 代码格式

```
{层级前缀}_{模块}_{错误描述}
```

### 层级前缀

| 前缀 | 层级 |
|------|------|
| WEB | Web 前端 |
| RUST | Rust 后端 |
| PY | Python 引擎 |
| CPP | C++ 求解器 |

### 示例错误代码

| 错误代码 | 说明 |
|----------|------|
| PY_TRAIN_GPU_OOM | 训练时 GPU 内存不足 |
| PY_SOLVE_TIMEOUT | 求解超时 |
| RUST_FILE_NOT_FOUND | 文件不存在 |
| RUST_FILE_LOCKED | 文件被占用 |
| WEB_VALIDATION_FAILED | 表单验证失败 |
| CPP_MEMORY_OVERFLOW | 内存溢出 |

## 错误处理层级

### 1. 全局错误边界（Error Boundary）

**作用：** 捕获未处理的组件错误，防止整个应用崩溃

**实现：**
- 在根布局 `+layout.svelte` 中包裹 ErrorBoundary 组件
- 捕获所有子组件的同步和异步错误
- 记录错误日志，显示友好提示

**用户提示：**
```
发生未知错误，请刷新页面重试。
如果问题持续存在，请导出日志并反馈。
```

### 2. API 层错误处理

**统一错误格式：**

```typescript
interface ApiError {
  code: string;        // 错误代码
  message: string;     // 用户友好的错误消息
  details?: any;       // 详细错误信息（调试用）
  level: 'warn' | 'error' | 'fatal';
}
```

**错误转换：**
- Rust 层捕获所有错误，转换为 ApiError 格式
- Python 引擎错误通过 stderr 捕获，解析后转换
- C++ 求解器错误通过返回值或异常捕获

### 3. 用户提示策略

| 错误级别 | 提示方式 | 持续时间 | 操作按钮 |
|----------|----------|----------|----------|
| warn | 黄色 Toast | 3秒自动消失 | 无 |
| error | 红色 Toast | 需手动关闭 | 查看详情、重试 |
| fatal | 模态对话框 | 阻塞操作 | 刷新页面、导出日志 |

**Toast 组件示例：**
```
⚠️ 训练失败：GPU 内存不足

建议：减少批次大小或切换到 CPU 模式
[查看详情] [切换到CPU]
```

## 具体场景处理

### 文件操作错误

#### 文件不存在
- **错误代码：** RUST_FILE_NOT_FOUND
- **处理方式：** 提示用户选择其他文件
- **提示信息：** "文件不存在，请选择有效的文件"

#### 文件被占用
- **错误代码：** RUST_FILE_LOCKED
- **处理方式：** 立即中断任务，提示用户关闭占用软件
- **提示信息：**
  ```
  生成失败：文件被占用
  
  文件：D:\OpenColor\default\gen_3mf\output.3mf
  原因：被 Bambu Studio 占用
  
  请关闭 Bambu Studio 后重试。
  ```

#### 权限不足
- **错误代码：** RUST_PERMISSION_DENIED
- **处理方式：** 提示检查文件权限
- **提示信息：** "无法访问文件，请检查文件权限或以管理员身份运行"

#### 磁盘已满
- **错误代码：** RUST_DISK_FULL
- **处理方式：** 提示清理磁盘空间
- **提示信息：** "磁盘空间不足，请清理后重试"

### 引擎调用错误

#### Python 未安装
- **错误代码：** RUST_PYTHON_NOT_FOUND
- **处理方式：** 引导用户安装 Python
- **提示信息：** "未检测到 Python，请先安装 Python 3.10+"

#### 引擎启动失败
- **错误代码：** PY_ENGINE_START_FAILED
- **处理方式：** 显示日志，建议重启
- **提示信息：** "引擎启动失败，请查看日志或重启应用"

#### 任务执行失败
- **错误代码：** PY_TASK_FAILED
- **处理方式：** 显示错误详情，提供重试
- **提示信息：** 显示具体错误原因和解决建议

### 长时间任务错误

#### 训练失败
- **处理方式：** 保存中间结果，允许从中断处恢复
- **提示信息：** "训练中断，已保存进度，可从中断处继续"

#### 求解失败
- **处理方式：** 提示调整参数后重试
- **提示信息：** "求解失败，建议调整参数：xxx"

## 文件锁定处理

### 处理原则

**直接中断，不重试。**

原因：
- 文件锁定通常不会自动解除
- 重试浪费时间和资源
- 给用户错误期望

### 常见锁定场景

| 文件类型 | 锁定软件 | 检测方式 |
|----------|----------|----------|
| 3MF | Bambu Studio, PrusaSlicer | 尝试读写打开 |
| SVG | Inkscape, Illustrator | 尝试读写打开 |
| PNG/JPG | Photoshop, 画图 | 尝试读写打开 |
| JSON | VS Code, 记事本 | 尝试读写打开 |

### 检测实现

```rust
// Rust 端
async fn check_file_accessible(path: &str) -> bool {
    match fs::OpenOptions::new()
        .read(true)
        .write(true)
        .open(path) {
        Ok(file) => {
            drop(file); // 立即关闭
            true
        }
        Err(_) => false,
    }
}
```

## 错误恢复机制

### 自动恢复

| 场景 | 恢复方式 |
|------|----------|
| 网络请求失败 | 自动重试 3 次，仍失败则提示用户 |
| 临时文件冲突 | 等待 1 秒后重试，仍失败则中断 |

### 手动恢复

| 场景 | 恢复方式 |
|------|----------|
| 任务失败 | 提供"重试"按钮 |
| 工作区损坏 | 提供"修复"或"新建"选项 |

## 修复功能

### 工作区索引损坏修复

**触发条件：**
- `index.json` 不存在
- `index.json` 格式错误（JSON 解析失败）
- `index.json` 缺少必要字段

**修复流程：**
1. 检测到损坏，提示用户
2. 扫描工作区目录结构
3. 识别各环节输出目录
4. 生成新的 `index.json`
5. 让用户确认或修改工作区名称

**提示信息：**
```
工作区索引损坏

检测到工作区索引文件损坏，是否尝试修复？
修复将扫描工作区目录并重建索引。

[修复] [放弃并新建工作区]
```

### 非修复类错误处理

以下情况不属于"修复"，而是"错误处理与用户引导"：

| 场景 | 处理方式 |
|------|----------|
| 样本数据集损坏 | 提示重新运行"样本提取"环节 |
| 输出文件不完整 | 提示重新运行该环节 |
| 临时文件堆积 | 提供"清理"按钮 |
| 设置文件损坏 | 自动重置为默认，通知用户 |
| 原始照片丢失 | 提示用户重新选择照片 |

## 错误日志

### 日志级别

| 级别 | 说明 | 存储方式 |
|------|------|----------|
| DEBUG | 开发调试信息 | 仅内存，不持久化 |
| INFO | 正常操作记录 | 内存 + 文件 |
| WARN | 警告（可恢复） | 内存 + 文件 |
| ERROR | 错误（需用户干预） | 内存 + 文件 + 通知 |
| FATAL | 致命错误（应用崩溃） | 内存 + 文件 + 弹窗 |

### 日志存储

- **内存中：** 保留最近 1000 条
- **文件位置：** `%APPDATA%/OpenColor/logs/`
- **文件命名：** `opencolor_YYYYMMDD_HHMMSS.log`
- **保留策略：** 保留最近 30 天的日志

### 日志导出

用户可导出日志用于反馈问题：
- 导出当前会话日志
- 导出最近 N 天日志
- 导出所有日志（压缩）

## 错误上报

### 自动上报（可选）

用户可选择开启自动错误上报：
- 只上报错误代码和堆栈
- 不上报文件路径等敏感信息
- 用户确认后才上报

### 手动反馈

提供反馈入口：
- 导出日志并附带描述
- 生成问题报告模板
- 链接到 GitHub Issues
