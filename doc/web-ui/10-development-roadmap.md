# 开发路线图

本文档定义 OpenColor WebUI 的开发周期，分为 5 个 Checkpoint，每个 Checkpoint 可独立验收。

## 总体时间规划

- **总周期：** 12-16 周（3-4 个月）
- **Checkpoint 数量：** 5 个
- **开发原则：** 每个 Checkpoint 可独立运行，为下一个 Checkpoint 提供基础

## Checkpoint 1：基础框架（2-3 周）

### 目标
搭建可运行的应用框架，验证技术栈，建立跨语言通信通路。

### 内容

#### 1.1 文件结构搭建
- 按 `08-file-structure.md` 创建目录结构
- 配置 SvelteKit 路由
- 配置 TypeScript、Vite

#### 1.2 路由系统
- 实现一级/二级导航
- 大窗口/小窗口布局切换
- 页面切换动画

#### 1.3 布局组件
- Sidebar 组件（导航）
- Header 组件（标题栏）
- 响应式布局容器

#### 1.4 主题与字体
- 深色/浅色主题切换
- Maple Mono 字体配置
- CSS 变量系统

#### 1.5 设置页面基础
- 通用设置页面框架
- 主题切换功能（持久化）
- 语言切换功能（i18n 基础）

#### 1.6 跨语言 API Ping
- Web → Rust 调用测试
- Rust → Python 调用测试
- Python 回传响应测试
- 连通性状态显示

### 验收标准

| 检查项 | 标准 |
|--------|------|
| 应用启动 | 可正常启动，无报错 |
| 布局切换 | 大窗口/小窗口模式切换正常 |
| 导航 | 可点击切换页面，URL 正确更新 |
| 主题切换 | 深色/浅色主题可切换，刷新后保持 |
| 语言切换 | 中英文可切换，刷新后保持 |
| API Ping | Web ↔ Rust ↔ Python 通信成功，状态显示正常 |
| 页面占位 | 未实现页面显示"开发中"提示 |

### 促进下一 Checkpoint
- 路由和布局为页面开发提供框架
- 组件库基础为页面开发提供工具
- 设置持久化机制为后续配置提供支持
- 跨语言通路验证为后端功能开发提供基础

---

## Checkpoint 2：工作区与文件系统（2 周）

### 目标
实现完整的工作区管理功能，包括文件系统操作。

### 内容

#### 2.1 工作区 API（Rust 端）
- `workspace_get_current`
- `workspace_set_current`
- `workspace_create`
- `workspace_list_recent`
- `workspace_remove_from_recent`

#### 2.2 文件系统 API（Rust 端）
- `file_select_dialog`
- `file_select_folder_dialog`
- `file_read_text`
- `file_write_text`
- `file_exists`

#### 2.3 工作区切换 UI
- 工作区选择器组件
- 最近工作区列表
- 工作区切换确认（未保存提示）

#### 2.4 新建/打开工作区
- 新建工作区对话框
- 选择自定义位置
- 打开其他工作区

#### 2.5 工作区目录结构
- 自动创建 `default` 工作区
- 创建 `index.json`
- 创建各环节子目录

#### 2.6 设置持久化
- APP 设置保存到系统目录
- 项目设置保存到工作区
- 当前工作区记忆

### 验收标准

| 检查项 | 标准 |
|--------|------|
| 默认工作区 | 首次启动自动创建 `Documents/OpenColor/default` |
| 目录结构 | 工作区包含所有环节子目录和 `index.json` |
| 新建工作区 | 可选择位置创建，时间戳命名正确 |
| 切换工作区 | 可切换到其他工作区，文件列表更新 |
| 最近列表 | 显示最近使用的工作区，可移除记录 |
| 设置保存 | APP 设置和项目设置可保存恢复 |

### 促进下一 Checkpoint
- 工作区为后续环节提供数据存储位置
- 文件系统 API 为后续文件操作提供基础
- 设置为后续环节提供默认配置

---

## Checkpoint 3：校准环节（3-4 周）

### 目标
实现校准流程的前 3 个环节：校准板生成、照片校正与样本提取、模型训练。

### 内容

#### 3.1 校准板生成页面
- 规格配置表单
- 生成按钮和进度显示
- 生成的文件列表

#### 3.2 照片校正与样本提取页面
- WarpCanvas 组件（透视校正画布）
- 角点拖拽交互
- 旋转和缩进控制
- SampleGrid 组件（样本网格）
- 格子启用/禁用切换
- 样本提取执行

#### 3.3 模型训练页面
- 训练配置表单
- 进度面板（含日志）
- 损失曲线图表
- 评估结果展示

#### 3.4 素材库基础
- 校准板列表页面
- 校准板详情（JSON 蓝图渲染）
- 文件预览

#### 3.5 API 实现
- `board_gen`
- `photo_warp`
- `sample_extract`
- `model_train_start/cancel`
- `library_list_boards`

### 验收标准

| 检查项 | 标准 |
|--------|------|
| 校准板生成 | 可生成规格文件和 3MF 文件 |
| 照片校正 | 可上传照片，拖拽角点，预览校正结果 |
| 样本提取 | 可提取样本，禁用/启用格子 |
| 模型训练 | 可配置并启动训练，查看实时进度和日志 |
| 素材库 | 可查看校准板列表和详情 |
| 数据保存 | 各环节输出正确保存到工作区 |

### 促进下一 Checkpoint
- 训练好的模型为生成环节提供输入
- Canvas 组件模式可复制到生成环节
- 素材库框架可扩展支持更多类型

---

## Checkpoint 4：生成环节（3-4 周）

### 目标
实现生成流程的后 4 个环节：叠色像素生成、矢量化、模型导出，以及完整的素材库。

### 内容

#### 4.1 叠色像素生成页面
- 图像选择和预览
- 参数配置（超分辨率、首层偏向等）
- 掩码预览和切换
- 误差热图显示

#### 4.2 矢量化页面
- 掩码选择
- 矢量化配置
- 进度显示
- SVG 预览

#### 4.3 模型导出页面
- 矢量文件选择
- 导出配置
- STL/3MF 预览
- 导出执行

#### 4.4 素材库扩展
- 照片列表和详情
- 模型列表和详情
- 材料管理
- 生成文件列表

#### 4.5 API 实现
- `mask_gen_start/cancel`
- `vectorize_start/cancel`
- `export_start/cancel`
- `library_list_photos/models/materials/exports`

### 验收标准

| 检查项 | 标准 |
|--------|------|
| 叠色像素 | 可从图像生成多层掩码，预览结果 |
| 矢量化 | 可将掩码转换为 SVG，预览矢量图形 |
| 模型导出 | 可导出 STL/3MF 文件，预览 3D 模型 |
| 素材库 | 支持所有类型（校准板、照片、模型、材料、导出文件） |
| 全流程 | 可从校准到导出完成完整流程 |

### 促进下一 Checkpoint
- 完整的 7 个环节已可用
- 全流程可验证
- 为优化阶段提供测试基础

---

## Checkpoint 5：完善与优化（2-3 周）

### 目标
产品化完善，包括错误处理、用户引导、性能优化。

### 内容

#### 5.1 错误处理实现
- 全局错误边界
- 错误提示组件（Toast、对话框）
- 文件锁定检测和提示
- 工作区索引损坏修复

#### 5.2 首次启动引导
- 欢迎页面
- 工作区创建引导
- 快速开始教程
- 帮助入口

#### 5.3 帮助文档集成
- 文档浏览页面
- 搜索功能
- 上下文帮助

#### 5.4 性能优化
- 大图像渲染优化
- 虚拟列表实现
- 缓存策略

#### 5.5 细节打磨
- 加载状态
- 空状态
- 过渡动画
- 快捷键支持

### 验收标准

| 检查项 | 标准 |
|--------|------|
| 错误处理 | 错误提示友好，可查看详情和日志 |
| 首次引导 | 新用户可独立完成首次校准 |
| 帮助文档 | 文档可访问，支持搜索 |
| 性能 | 大图像和大量数据无明显卡顿 |
| 稳定性 | 无明显崩溃或数据丢失 |

## 依赖关系

```
Checkpoint 1: 基础框架
     ↓
Checkpoint 2: 工作区与文件系统
     ↓
Checkpoint 3: 校准环节 ← 依赖工作区存储数据
     ↓
Checkpoint 4: 生成环节 ← 依赖校准环节的模型
     ↓
Checkpoint 5: 完善与优化 ← 依赖完整流程验证
```

## 验收流程

每个 Checkpoint 结束后：

1. **代码审查** - 确保代码质量
2. **功能演示** - 演示所有验收标准
3. **文档更新** - 更新相关文档
4. **确认进入下一阶段** - 双方确认后再继续

## 风险与应对

| 风险 | 应对策略 |
|------|----------|
| 跨语言通信复杂 | Checkpoint 1 优先验证通路 |
| Canvas 交互复杂 | Checkpoint 3 预留充足时间 |
| 大文件处理性能 | Checkpoint 4 关注，Checkpoint 5 优化 |
| 需求变更 | 每个 Checkpoint 确认后再继续 |
